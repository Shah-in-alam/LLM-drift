# v0.2 Thin Slice — `drift run` + cosine drift report

**Date:** 2026-05-06
**Builds on:** [`2026-05-05-v0.1-slice-design.md`](2026-05-05-v0.1-slice-design.md)
**Scope:** Add the actual drift comparison. `drift run` captures a new evaluation run and compares each prompt's response embedding against the latest baseline using cosine similarity, emitting a markdown report and a pass/fail exit code.

## Goal

A new CLI command `drift run` that:

1. Captures responses + embeddings for the prompt suite (same flow as `drift baseline`, but `kind="eval"`).
2. Compares each prompt's new embedding against the most recent baseline run's embedding for the same `prompt_id`, using cosine similarity.
3. Writes a markdown report to `reports/run-<eval_run_id>.md`.
4. Exits 1 if any compared prompt's similarity is below `--threshold`, else 0.

## Non-goals (for this slice)

- No PSI, KL divergence, or rolling-window aggregates. Cosine only.
- No multiple samples per prompt. Single sample, deterministic temperature 0.
- No Slack alerts, no scheduling, no dashboard.
- No provider abstraction or Anthropic backend.
- No re-baselining or "rolling baseline" logic.

## CLI

```
drift run [--prompts PATH] [--db PATH] [--threshold FLOAT] [--report-dir PATH]
```

Defaults:
- `--prompts prompts/example.yaml`
- `--db drift.db`
- `--threshold 0.95`
- `--report-dir reports`

## Baseline selection

Always the most recent `runs` row with `kind="baseline"`. No flag for picking a specific baseline in this slice.

If no baseline exists, exit 1 with `"No baseline run found. Run 'drift baseline' first."` and **do not** create an eval run row.

## Mismatched prompt sets

- Prompt in eval but not in baseline → report as `[new]`. Not a threshold failure.
- Prompt in baseline but not in eval → report as `[missing]`. Not a threshold failure.
- Prompt in both → cosine similarity compared against the threshold.

A prompt with no comparison (new or missing) cannot trigger failure but is still surfaced in the report so the user sees that prompt sets diverged.

## Markdown report

Path: `<report-dir>/run-<eval_run_id>.md`. The `report-dir` is created if missing.

Shape:

```
# Drift report — run <eval_id> (eval) vs run <baseline_id> (baseline)

- date: <ISO 8601 UTC>
- model: <chat_model>, embedding: <embedding_model>
- threshold: <threshold>
- result: PASS | FAIL (<failed>/<compared> prompts below threshold)

## <prompt_id> — sim <0.000> ✓ | ✗
**Baseline:** <baseline response>
**Now:** <eval response>

## <prompt_id> — [new]
**Now:** <eval response>

## <prompt_id> — [missing]
**Baseline:** <baseline response>
```

Sections are listed in YAML order for prompts present in eval, then `[missing]` prompts at the bottom.

## New / changed code

- **`src/drift/metrics.py`** (new) — `cosine(a: list[float] | np.ndarray, b: ...) -> float`. Pure numpy.
- **`src/drift/report.py`** (new) — `build_markdown(eval_run, baseline_run, comparisons, threshold) -> str`. Pure function, no I/O.
- **`src/drift/storage.py`** — add:
  - `latest_baseline_run(conn) -> dict | None`
  - `responses_for_run(conn, run_id) -> list[dict]` (returns rows with embeddings already deserialized)
- **`src/drift/runner.py`** — add `run_eval(prompts_path, db_path, threshold, report_dir) -> int`. Returns process exit code.
- **`src/drift/cli.py`** — add `run` typer command wired to `run_eval`.

`run_baseline` and `run_eval` share substantial logic (load prompts, init db, insert run row, loop calling chat+embed and inserting responses). Extract a private `_capture_run(conn, kind, prompts) -> tuple[int, int]` helper in `runner.py` that returns `(run_id, failures)`. Both `run_baseline` and `run_eval` call it; `run_eval` then runs the comparison + report step on top.

## Data flow (`drift run`)

```
drift run --prompts ... --db ... --threshold 0.95 --report-dir reports/
  └─ load API key (fail-fast)
  └─ load + validate prompts YAML
  └─ open SQLite
  └─ baseline = latest_baseline_run(conn); exit 1 if None
  └─ (run_id, failures) = _capture_run(conn, kind="eval", prompts)
  └─ baseline_responses = responses_for_run(conn, baseline.id)  # dict by prompt_id
  └─ eval_responses     = responses_for_run(conn, run_id)
  └─ build comparisons:
       for prompt_id in union(baseline, eval):
         if both present: similarity = cosine(b_emb, e_emb); status = ok/fail
         if only eval:    [new]
         if only baseline:[missing]
  └─ markdown = build_markdown(...); write to reports/run-<id>.md
  └─ print one-line summary: "Drift report: PASS|FAIL — wrote reports/run-7.md"
  └─ exit 1 if any [fail] OR if capture had failures, else 0
```

## Error handling

- Missing API key → exit 1, same message as v0.1.
- Invalid YAML → exit 1 with pydantic error.
- No baseline exists → exit 1 with clear message; no eval run row inserted.
- Provider call fails for a prompt → log `[fail]`, skip storing that response, continue. Counts toward `failures`. Eval continues; comparison still runs over whatever did get stored. Exit 1 at the end if any failures.

## Testing

- **`tests/test_storage.py`** — extend with `test_latest_baseline_run` (insert two baselines, check it returns the newer one; insert no baselines, check it returns None) and `test_responses_for_run` (insert + retrieve, embeddings parsed back to lists).
- **`tests/test_metrics.py`** (new) — cosine of identical vectors == 1.0; cosine of orthogonal == 0.0; cosine of negated vectors == -1.0.
- **`tests/test_report.py`** (new) — given fake `eval_run`, `baseline_run`, and a comparisons list with one ✓ / one ✗ / one `[new]` / one `[missing]`, assert the markdown contains: the title with both run ids, the threshold line, a `result: FAIL` line, and one `## ` header per prompt.

No live-API tests; `drift run` is validated manually by running it after a real baseline.

## Dependencies

No new dependencies. `numpy` is already pulled in from v0.1.

## Acceptance criteria

1. `pytest` passes all tests (storage + metrics + report).
2. With a baseline captured and `drift run` immediately after (same prompts), all similarities are ≥ 0.99 and the report says PASS. (Manual.)
3. Adding a new prompt to the YAML between baseline and run shows up as `[new]` in the report; removing one shows up as `[missing]`.
4. `drift run` with no prior baseline exits 1 with a clear message and creates no DB rows.
5. `drift run` with `--threshold 0.999` against a noisy real model produces a FAIL exit code 1.

## What's next (still not in this slice)

- Multiple samples per prompt (`--samples N`) to distinguish noise from drift.
- PSI / KL divergence over a rolling window of eval runs.
- Provider abstraction + Anthropic backend.
- Slack alert on FAIL.
- Scheduled runs.
