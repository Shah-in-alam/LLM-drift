

# v0.1 Thin Slice — Design

**Date:** 2026-05-05
**Scope:** First working vertical slice of the LLM Drift Detector. Goal is to prove the pipeline end-to-end (provider call → embedding → storage), not to detect drift yet.

## Goal

A CLI command `drift baseline` that:

1. Reads a small YAML prompt file.
2. For each prompt, calls OpenAI chat (`gpt-4o-mini`) and gets a response.
3. Embeds the response with `text-embedding-3-large`.
4. Stores `(prompt, response, embedding, run metadata)` in SQLite.
5. Prints a one-line summary per prompt.

Drift comparison is explicitly out of scope here. That is the next slice.

## Non-goals (for this slice)

- No vector store (Chroma/Qdrant). Embeddings stored as JSON in SQLite.
- No drift metrics (cosine, PSI, KL).
- No scheduling, no Slack alerts, no dashboard.
- No multi-provider abstraction beyond a single `providers/openai.py` module — we will refactor when the second provider lands.
- No retries or rate-limit handling.

## Stack

- Python 3.11+ managed by `uv`.
- Provider: OpenAI (chat + embeddings).
- Storage: SQLite, single file `drift.db`.
- CLI: `typer`.
- Config: `python-dotenv` for `.env`, `pydantic` for schema.

## Data model (SQLite)

```sql
CREATE TABLE runs (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  started_at      TEXT NOT NULL,         -- ISO 8601 UTC
  model           TEXT NOT NULL,         -- e.g. "gpt-4o-mini"
  embedding_model TEXT NOT NULL,         -- e.g. "text-embedding-3-large"
  kind            TEXT NOT NULL          -- "baseline" for this slice
);

CREATE TABLE responses (
  id             INTEGER PRIMARY KEY AUTOINCREMENT,
  run_id         INTEGER NOT NULL REFERENCES runs(id),
  prompt_id      TEXT NOT NULL,          -- stable id from YAML, e.g. "greet"
  prompt_text    TEXT NOT NULL,
  response_text  TEXT NOT NULL,
  embedding_json TEXT NOT NULL           -- JSON array of floats
);

CREATE INDEX idx_responses_run_prompt ON responses(run_id, prompt_id);
```

Embeddings stored as JSON arrays for simplicity. When we move to a real vector store, this column becomes the migration source.

## Prompt file format (`prompts/example.yaml`)

```yaml
- id: greet
  text: "Say hello in one short sentence."
- id: math
  text: "What is 13 * 47? Answer with just the number."
- id: refusal
  text: "Briefly explain why you would not write malware."
```

Schema (validated by `pydantic`):
- `id`: string, unique within file, used as stable key across runs.
- `text`: string, the user prompt.

System prompt and chat parameters (temperature, max_tokens) are hardcoded in `runner.py` for v0.1. Making them per-prompt is a later slice.

## Component responsibilities

- **`config.py`** — loads `.env`, exposes `OPENAI_API_KEY`. Exits with a clear message if missing.
- **`providers/openai.py`** — two functions: `chat(prompt: str) -> str` and `embed(text: str) -> list[float]`. No abstraction layer yet; just a thin wrapper around the SDK.
- **`storage.py`** — `init_db(path)`, `insert_run(...)`, `insert_response(...)`. Uses `sqlite3` from stdlib. Schema is created on first run if missing.
- **`runner.py`** — `run_baseline(prompts_path, db_path)`: orchestrates the loop. Loads YAML, validates with pydantic, creates a run row, iterates prompts, calls provider, stores result, prints status.
- **`cli.py`** — single `typer` command `drift baseline --prompts <path> --db <path>`. Defaults: `prompts/example.yaml` and `drift.db`.

## Data flow

```
drift baseline --prompts prompts/example.yaml --db drift.db
  └─ load .env (config.py)
  └─ load + validate YAML (runner.py)
  └─ init SQLite (storage.py)
  └─ insert runs row, kind="baseline"
  └─ for each prompt:
       ├─ openai.chat(prompt.text)        → response_text
       ├─ openai.embed(response_text)     → embedding (3072 floats)
       ├─ storage.insert_response(...)
       └─ print "[ok] prompt_id=greet (1234 chars, 3072-dim)"
  └─ print "Baseline complete: 3/3 prompts captured. run_id=1"
```

## Error handling

- Missing `OPENAI_API_KEY` → exit 1, message: `"OPENAI_API_KEY not set. Copy .env.example to .env and fill it in."`
- Invalid YAML → exit 1 with the pydantic validation error.
- Provider call raises → log `[fail] prompt_id=X: <error>`, continue with next prompt. Exit code 1 if any failures occurred, 0 otherwise.
- No retries in v0.1. A failed prompt is just skipped.

## Testing

One unit test: `tests/test_storage.py` exercises the SQLite round-trip — create schema in a temp file, insert a run + response, read it back, assert equality. No live API tests; the provider call is validated manually by running the CLI once OpenAI keys are configured.

## Dependencies

Runtime: `openai`, `pyyaml`, `pydantic`, `python-dotenv`, `typer`, `numpy` (pulled in now even though unused this slice — the next slice needs it).
Dev: `pytest`.

## Acceptance criteria

1. `uv sync` installs cleanly on Windows.
2. `drift baseline` with a valid `OPENAI_API_KEY` runs the example prompts, prints per-prompt status lines, and exits 0.
3. Inspecting `drift.db` shows one row in `runs` and N rows in `responses` (N = number of prompts).
4. `pytest` passes the storage round-trip test.
5. Missing API key produces a clear error and exit code 1.
