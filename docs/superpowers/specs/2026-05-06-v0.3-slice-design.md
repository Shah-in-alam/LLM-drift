# v0.3 Thin Slice — Chat provider abstraction + Anthropic backend

**Date:** 2026-05-06
**Builds on:** `2026-05-06-v0.2-slice-design.md`
**Scope:** Add a small chat-provider abstraction so the model under test can be either OpenAI or Anthropic. Embeddings remain OpenAI-only this slice. Records the provider in the database, surfaces it in the report, and refuses to compare baseline+eval runs that used different providers.

## Goal

- A `ChatProvider` protocol with `name`, `chat_model`, and `chat(prompt) -> str`.
- Two backends: `openai_provider` (existing) and `anthropic_provider` (new, default model `claude-sonnet-4-6`).
- `--provider openai|anthropic` flag on `drift baseline` and `drift run`.
- `drift run` without `--provider` defaults to whatever provider the latest baseline used.
- Cross-provider comparison is refused with a clear error.
- Reports show which provider was used.

## Non-goals (for this slice)

- Embedding-provider abstraction (Voyage, etc.) — embeddings always use OpenAI `text-embedding-3-large`.
- Per-prompt provider override.
- Provider-level retries, rate-limit handling, or fallback chains.
- Anthropic chat parameter exposure beyond the hardcoded `temperature=0` and a fixed system prompt.

## Provider protocol

```python
# src/drift/providers/base.py
from typing import Protocol

class ChatProvider(Protocol):
    name: str         # "openai" or "anthropic"
    chat_model: str   # backend-specific model id

    def chat(self, prompt: str) -> str: ...
```

Concrete backends are simple classes (or modules) implementing this. The factory:

```python
# src/drift/providers/__init__.py
def get_provider(name: str) -> ChatProvider: ...
def get_embedder() -> Callable[[str], list[float]]: ...
```

Unknown name → `ValueError("Unknown provider: <name>. Choices: openai, anthropic.")`.

`get_embedder()` always returns the OpenAI `embed` function this slice — but routing through a factory means the embedder swap in v0.4+ touches only one place.

## Backends

### OpenAI (`providers/openai_provider.py`)

Refactor from current `providers/openai.py`. Class with:
- `name = "openai"`
- `chat_model = "gpt-4o-mini"`
- `chat(prompt)` calls the existing chat completions API at `temperature=0` with the existing system prompt.

The `embed` function moves to `providers/openai_embed.py` (still owned by the OpenAI module but separated so the embedder factory can import it without dragging in the chat backend's per-call overhead).

### Anthropic (`providers/anthropic_provider.py`)

- `name = "anthropic"`
- `chat_model = "claude-sonnet-4-6"`
- Uses the `anthropic` SDK:
  ```python
  client.messages.create(
      model=self.chat_model,
      system=_SYSTEM_PROMPT,
      messages=[{"role": "user", "content": prompt}],
      max_tokens=1024,
      temperature=0,
  )
  ```
- Returns `response.content[0].text` (asserts a single text block; anything else raises so we don't silently lose content).
- Lazy-initializes a singleton `anthropic.Anthropic` client, mirroring the OpenAI module pattern.

## Config

- `config.py` adds `load_anthropic_api_key() -> str` (same pattern as `load_openai_api_key`).
- Each provider calls its own loader on first use. The runner doesn't need to know which keys are required — `_capture_run` calls `provider.chat(...)`, and any missing key fails fast inside the provider's loader before any API call.
- The OpenAI key is *always* required (embeddings use it) regardless of `--provider`. The Anthropic key is required only when `--provider anthropic`.
- `.env.example` gains:
  ```
  ANTHROPIC_API_KEY=sk-ant-replace-me
  ```

## Storage migration

Add column to `runs`:

```sql
ALTER TABLE runs ADD COLUMN provider TEXT NOT NULL DEFAULT 'openai';
```

On `connect()`, after running the schema script, query `PRAGMA table_info(runs)`. If `provider` is not in the column list, run the `ALTER TABLE`. Existing rows backfill to `"openai"` via the column default.

`insert_run` gains a `provider: str` keyword argument and inserts it.

`latest_baseline_run` and `responses_for_run` already return `dict(row)`, so the new column flows through automatically.

## CLI

- `drift baseline --provider {openai,anthropic}` — default `openai`.
- `drift run [--provider {openai,anthropic}]` — default = latest baseline's provider.
- Both pass the resolved provider name into the runner.

## Runner changes

- `_capture_run(conn, *, provider: ChatProvider, prompts) -> tuple[int, int]`:
  - Persists `provider.name` and `provider.chat_model` into the runs row (also `EMBEDDING_MODEL` from config, unchanged).
  - Calls `provider.chat(prompt.text)` instead of the module-level function.
  - Calls `get_embedder()(response)` for embeddings.

- `run_baseline(prompts_path, db_path, provider_name)`:
  - `provider = get_provider(provider_name)`
  - Existing flow, plus the new `provider` arg threaded through.

- `run_eval(prompts_path, db_path, threshold, report_dir, provider_name: str | None)`:
  - Open db (after `db_path.exists()` check unchanged).
  - `baseline = latest_baseline_run(conn)` — exit 1 if None (unchanged).
  - If `provider_name is None`: use `baseline["provider"]`.
  - Else if `provider_name != baseline["provider"]`: print `"Cannot compare: latest baseline used '<X>', requested provider is '<Y>'."` and exit 1 *before* capturing.
  - `provider = get_provider(provider_name)`
  - Continue with existing capture + comparison + report flow.

## Report

In the header block, add:

```
- provider: <name> (<chat_model>)
```

This makes drift reports self-describing — you can tell at a glance whether a run targeted Claude or GPT.

## Dependencies

Runtime: add `anthropic>=0.40.0`.

## Acceptance criteria

1. `pytest` passes all tests (12+).
2. `drift baseline --provider anthropic` (with `ANTHROPIC_API_KEY` set) captures a baseline using `claude-sonnet-4-6`, recorded as `provider="anthropic"`. Manual.
3. `drift run` (no flag) after an Anthropic baseline auto-uses Anthropic. Manual.
4. `drift run --provider openai` against an Anthropic baseline exits 1 with the cross-provider error and inserts no eval run row.
5. An existing v0.2 `drift.db` (no `provider` column) opens cleanly under the new code; a `latest_baseline_run` against it returns a row with `provider="openai"`.
